## 摘要
在线脑机接口研究需要能够采集多模态生理数据、训练并更新解码器、执行实时推理，并在可复现的工作流程中保留完整实验来源的软件。我们提出了Dendrite，一个实时的脑机接口Python应用程序，它将信号采集、解码器训练和实时推理整合到一个可修改的即用型应用中。Dendrite可以同时记录多个信号流，每个信号流以其原有采样率运行，并并发地执行多种处理模式。解码器可以从先前训练的模型开始，也可以在管线持续运行时在会话中训练，而同一记录可以在同一应用程序中用于离线训练。每个记录、解码器和训练运行都在数据库中进行追踪，每个解码器还记录了其配置和训练所用的源记录，因此部署的解码器可以追溯到产生它的数据。实验范式保持外部化，是一个独立的程序，可以使用任何语言并通过网络连接到Dendrite，而不是构建在运行时内部的模块。我们使用内部和公开的BCI数据集对完整系统进行端到端验证，在管线实时运行的同时在线训练和更新解码器。Dendrite在GPL-3.0许可证下开源，网址为https://github.com/dendrite-bci/dendrite。最终成果是一个可复现、开源、用于开发和评估在线BCI范式的生物医学计算系统。

## Abstract
Online brain-computer interface research requires software that can acquire multimodal physiological data, train and update decoders, run live inference, and preserve the full experimental provenance in a reproducible workflow. We present Dendrite, a real-time brain-computer interface application in Python that brings signal acquisition, decoder training, and live inference together in a single, ready-to-run application that stays modifiable. Dendrite records several signal streams at once, each at its native rate, and executes multiple processing modes concurrently against them. A decoder can start from a previously trained model or be fit mid-session while the pipeline keeps running, and the same recordings feed offline training in the same application. Each recording, decoder, and training run is tracked in a database, and every decoder records the configuration and the source recordings it was trained from, so a deployed decoder traces back to what produced it. The experimental paradigm stays external, an independent program in any language that reaches Dendrite over the network, rather than a module built inside the runtime. We validate the full system end-to-end on in-house and public BCI datasets, training and updating decoders online while the pipeline runs in real time. Dendrite is open-source under the GPL-3.0 license at https://github.com/dendrite-bci/dendrite. The result is a reproducible, open-source biomedical-computing system for developing and evaluating online BCI paradigms.

## 2. 方法论

*   **核心思想**：Dendrite 将硬件无关的信号采集、多模式并发处理、可在训练/推理间无缝切换的解码器，以及完整的出处追踪融合在一个 Python 运行时中，并通过 Lab Streaming Layer (LSL) 契约将实验范式（如刺激呈现）放在外部独立程序里。
*   **系统架构（四层 + 一个契约）**：
    *   **数据层（Data Layer）**：通过 LSL 采集任意多模态流（EEG、EMG、事件标记等），每种流以原生速率在专用线程中写入**共享内存环形缓冲区（zero‑copy ring buffer）**，实现多发布者/多订阅者解耦。数据以 HDF5 + SQLite 存储，元数据采用 BIDS 风格标记，支持 SWMR（单写多读）模式，允许在记录中同时进行实时训练和离线读取。
    *   **处理层（Processing Layer）**：三个独立子进程模式从环形缓冲区读取数据：
        1.  **同步模式（Synchronous mode）**：事件锁定，每次标记后提取试次 epoch，进行每试次预测，并每 N 个试次发起解码器重训练；新的解码器通过共享状态热切换到链接的异步模式。
        2.  **异步模式（Asynchronous mode）**：以滑动窗口进行连续分类，输出类别与置信度。支持解码器热切换，不中断推理。
        3.  **神经反馈模式（Neurofeedback mode）**：估计指定频段的功率（如 α 波段），以固定速率输出，用于闭环调制训练。
        *   各模式独立管理预处理链（因果 IIR 滤波、公共平均参考、降采样等），共享环形缓冲区，无队列阻塞。
    *   **机器学习层（Machine Learning Layer）**：所有解码器（如 EEGNet、CSP+LDA、xDAWN+切线空间）统一封装为 scikit‑learn 的 `fit`/`predict` 接口，支持 CPU/CUDA/MPS 后端。离线超参数搜索（Optuna）和在线训练共用同一接口，训练服务在独立子线程中通过 SWMR 读取实时文件，不阻塞数据采集与在线推理。
    *   **网络界面层（Web Layer）**：FastAPI 后端提供 REST API 和 WebSocket 通道，供 Vue 3 单页应用进行实时监控、数据探索和离线训练（ML Workbench）。
    *   **任务应用契约**：外部范式程序（任何语言）通过 LSL 发送 JSON 事件标记并订阅预测流（LSL/ROS2/TCP/UDP/ZeroMQ），实现闭环控制，范式逻辑与运行时完全解耦。
*   **出处追踪**：每个记录、训练任务和解码器均在 SQLite 中记录关联，部署的解码器可追溯到其配置和源记录 ID，保证审计性。

## 3. 实验设计

*   **数据集与场景**：
    *   **内部运动想象（MI）数据集**：4 个会话，单被试，64 通道 EEG (500 Hz)，两分类 MI（CSP+LDA 解码）。
    *   **公开数据集 BNCI 2014‑001**：BCI 竞赛 IV‑2a，9 名被试，22 通道 EEG (250 Hz)，4 类 MI，通过 MOABB 加载。
    *   **公开数据集 BNCI 2014‑009**：10 名被试 P300 怪异球范式 (256 Hz)，2 分类目标/非目标，使用 xDAWN+切线空间逻辑回归。
    *   **内部外骨骼录制**：多模态（EEG 64ch @500 Hz，EMG 3ch @2148 Hz，外骨骼运动学 @100 Hz），用于展示同步采集能力。
    *   **闭环节奏延迟测试**：5 名被试实时神经反馈会话，通过外部应用测量端到端延迟。
*   **Benchmark/对比方法**：并非与其它 BCI 软件平台对比解码性能，而是通过**前叙准确率（prequential accuracy）**、Cohen’s $\kappa$、实时推理延迟和闭环节拍率来验证系统在真实条件下支持在线训练、热切换与实时输出的可行性。同步模式每 10 个 epoch 重训练一次，使用指数遗忘因子 0.95 报告平滑后的前叙准确率。

## 4. 资源与算力

*   论文**未明确提及**训练解码器所用的 GPU 型号、数量、显存容量或具体训练时长。仅提及机器学习层支持 CUDA 和 MPS 后端，且训练在独立子进程中执行，不阻塞主循环。轻量模型如 CSP+LDA 显然可在 CPU 上快速完成。实时推理延迟测量显示计算时间极短（毫秒级）。

## 5. 实验数量与充分性

*   **实验组数**：围绕 4 个数据集（内部 MI、BNCI 2014‑001、BNCI 2014‑009、外骨骼多模态）以及额外的实时神经反馈会话进行了端到端测试。
*   **评估维度**：覆盖了在线学习曲线、实时推理延迟（分位数 $p_{50}$、$p_{99}$）、闭环节奏吞吐、多模态同步采集展示，以及出处记录的完整性。
*   **充分性与客观性**：实验设计并非严格的消融对比或与 BCI2000/MetaBCI 等平台的横向基准测试，而是作为系统级的**可行性验证（feasibility demonstration）**。评估较全面地覆盖了实时管道的关键指标，但在被试数量、会话长度、解码器收敛后性能与离线最优结果的对比方面较为简单，缺乏与现有平台的直接功能或性能对比。

## 6. 主要结论与发现

*   Dendrite **成功整合**了多模态采集、实时处理、在线解码器训练/热切换、离线重放与闭环节输出，所有环节均运行在同一个 Python 应用中。
*   在线训练的解码器在三个 BCI 范式中均达到了可用的性能（MI：$\kappa$ 均值 0.31‑0.36；P300：$\kappa$ 均值 0.46），且重训练（0.3‑0.4 秒）不影响推理流。
*   实时推理延迟极低：轻量级解码器每步 1‑2 ms，P300 管线 1.4‑3.8 ms（$p_{99}$）。在真实闭环节奏神经反馈中，包括传输的应用端端到端延迟为 $p_{50} \approx 13$ ms，$p_{99} \approx 66$ ms，瓶颈主要在传输而非计算。
*   通过 HDF5+SQLite 存储与 BIDS 启发的标识符，实现了**完整的实验出处追踪**，每个解码器可追溯到其训练配置和数据。

## 7. 优点

*   **全流程整合**：将采集、处理、训练、推理、数据探索、出处保存统一在单一 Python 应用中，大幅减少工具碎片化。
*   **灵活性与可修改性**：全部基于 Python 科学栈（MNE、sklearn、PyTorch/Braindecode），研究者可直接修改管道；外部范式通过 LSL 事件契约任意替换，范式与运行时解耦。
*   **实时鲁棒性**：多模式并发且独立进程，解码器热切换不间断输出，环缓冲结构避免慢消费者阻塞采集。
*   **出处可复现**：每个训练出的解码器都记录来源，支持从会话到模型的完整追溯。
*   **低延迟**：推理计算延迟远低于常见的 BCI 闭环窗口（如 100 ms），传输主导的端到端延迟亦在可接受范围。

## 8. 不足与局限

*   **无内置刺激呈现**：任务范式完全外部化，因此 Dendrite 本身不包含任何刺激呈现软件，初始搭建需用户额外开发任务应用，起点高于某些一体化平台（如 BCI2000）。
*   **多模态解码限制**：目前解码仅在各模态流上独立进行，仅在输出层融合，系统不支持在运行时训练跨模态联合解码器。
*   **缺乏插件 API**：扩展新功能（如新解码器或处理模式）需要直接修改源代码，无法以外部插件包形式安装，扩展需在分支或上游中维护。
*   **实验验证有限**：仅使用小规模的内部数据和少量公开数据集进行在线曲线测试，未与主流 BCI 软件平台（如 OpenViBE, MEDUSA）进行横向对比，统计稳健性（被试数、跨会话泛化）较弱。
*   **解码策略简化**：在线学习采用简单的“每 N 试次从头重训练”策略，作为管道应力测试而非高级自适应算法演示，更复杂的在线更新/迁移学习未纳入评估。
