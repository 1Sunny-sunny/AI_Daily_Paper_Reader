# HP-GSBS: Accelerating greedy state boundary search with reusable interval statistics 

Yanzhe Zhao a, ∗, Yongzhang Ji b

> aSchool of Future Technology, Tianjin University, Tianjin, China
> bFaculty of Psychology, Southwest University, Chongqing, China

Abstract 

Greedy State Boundary Search (GSBS) identifies transitions between relatively stable neural activity patterns, but repeated candidate evaluation makes large analyses expensive. HP-GSBS is an open-source Python package that reorganizes the search around reusable interval contributions and correlation statistics. Streaming candidate reduction and local refinement further reduce repeated work; CPU, PyTorch CUDA and Triton backends share sequential segmentation decisions. Across seven controlled workloads with two realizations each, median same-input speedups range from 154 to 1730 times. All 168 optimized executions reproduce original boundaries and selected state counts, with maximum absolute t-distance difference 1 .88 × 10 −11 . Four frozen EEG recordings provide complementary validation, including a complete input-to-segmentation application example. Batch processing, versioned result persistence and optional low-memory execution support recording collections and longer inputs. By removing redundant computation, HP-GSBS makes established neural-state segmentation faster while preserving its scientific outputs. 

Keywords: neural state segmentation, GSBS, EEG, GPU computing 

Required metadata 1. Motivation and significance 

Natural experience unfolds continuously, yet neural activ-ity often remains relatively stable within an event before changing at a boundary. Data-driven segmentation links this temporal organization to perception and memory [1]. Greedy State Boundary Search (GSBS) identifies the posi-tions and number of neural states [2]; its statewise exten-sion has revealed a partially nested hierarchy of transitions across cortex [3]. The computational bottleneck lies inside the search. Each candidate boundary repeatedly triggers state-mean recon-struction and comparison with the observed series. Double-boundary search considers pairs of positions within a state, expanding the candidate space quadratically with interval length. Refinement revisits existing boundaries after inser-tions, repeating calculations for intervals whose data have not changed. These costs accumulate across participants, stimuli and feature sets. HP-GSBS [4] reorganizes this computation around reusable statistics. Interval contributions replace repeated template reconstruction, correlation prefixes replace repeated pair-wise scans, and streaming search retains the best candidate without a dense candidate-score array. CPU and GPU im-plementations share the sequential search controller. The

Unlike Q, which scores interval templates, these tables summarize time-pair correlations for partition comparison. After interval end-points are available, evaluating a partition requires O(K)queries rather than rescanning all time pairs. The tempo-ral exclusion parameter dmin is encoded in the pair mask. GSBS then accepts one or two boundaries and refines them sequentially. The CPU backend uses NumPy/SciPy [8, 9] and Numba-compiled search [10]. PyTorch CUDA batches matrix prod-ucts and prefix operations [11]; Triton fuses interval differ-ences, dot products and norms [12]. GPU routes transfer precomputed statistics to the shared CPU controller, as-signing regular numerical work to the accelerator while preserving sequential search dependencies. 

2.2. Software functionalities 

A configuration separates scientific parameters from ex-ecution choices. Users retain their statewise detection, maximum state count, block size, temporal exclusion and refinement settings. Results expose boundaries at every state-count index, t-distance, state patterns and bound-ary strengths. A typical workflow fits a prepared input, retrieves its segmentation, saves a reusable result and pro-cesses a collection:    

> from hpgsbs import GSBSConfig, GSBSResult, fit, fit_many cfg = GSBSConfig(kmax=20, dmin=1, mode="throughput") r = fit(x, cfg, backend="cpu-fast") bounds, curve = r.get_bounds(r.nstates), r.tdists r.save("results/recording.npz") restored = GSBSResult.load("results/recording.npz") batch = fit_many(recordings, cfg, backend="torch-cuda", batch_size="auto")

CPU workers fit recordings independently; GPU batches group compatible shapes and configurations. The manifest-based command-line workflow saves outputs atomically and resumes completed tasks only when input and ver-sioned execution identities match. Output comparison checks complete boundary histories and numerical fields; optional traces compare search and refinement decisions. The versioned wheel/sdist, tests and examples support in-stallation and reuse. Supplementary Section S3 gives a CPU-compatible workflow and recovery example. FP64 is the default, with reference-expression reevaluation for ambiguous calculations. Full-Q/Prefix2D is the ordinary fast route. An optional CPU mode uses bounded candidate chunks and feature-moment t-distance statistics to avoid full pairwise tables; its double-candidate domain can still be quadratic. Supplementary Methods S2–S3 describe this trade-off.

3.2. Real EEG application 

Four frozen inputs derived from the Brain, Body, and Behavior Dataset [13] provide application-level evidence. These 5.12-Hz matrices span 32 or 64 channels and 1336– 1857 samples. Boundary histories and selected state counts match their reference outputs across the three backends (Table 2). Figure 3 follows Recording 1 from its full 64-channel input to the selected state sequence. A fixed central excerpt links the detected boundaries to the temporal pattern-similarity matrix. All routes select 126 states and reproduce the complete boundary history, with maximum TD difference 2.43 × 10 −13 . Local views are extracted from saved full-record fits, connecting the input, state intervals and state-count selection without refitting the excerpt.

4. Impact 

HP-GSBS makes repeated neural-state analysis practical within a research workflow. Tens or hundreds of seconds become subsecond fits in the controlled benchmark, al-lowing researchers to iterate across participants, stimuli and feature sets. Batch scheduling extends this benefit to recording collections, while saved boundary histories and t-distance curves support later state-count comparisons without repeating the fit. Historical release benchmarks extend this picture to larger inputs (Supplementary Table S6). For 2100 × 64 and 

Kmax = 50, recorded official runtime is approximately 5011 s and release-wheel PyTorch runtime is 0.363 s. This sepa-rate cross-session comparison illustrates the change from an hour-scale task to subsecond processing; the paired experiment supplies the primary speedup estimates. The common interface lets researchers choose CPU workers or GPU batching according to workload, retain their pre-processing and scientific parameters, and inspect numerical agreement before adoption. Full-Q prioritizes latency at quadratic storage cost, whereas the optional low-memory route supports longer restricted workloads. The evidence covers laptop-class hardware and four frozen EEG records; the open implementation provides a basis for wider appli-cations. 

5. Conclusions 

HP-GSBS accelerates neural-state segmentation by com-puting reusable interval statistics and concentrating subse-quent work on changing parts of the partition. CPU and 7GPU implementations reproduce original boundary deci-sions across controlled synthetic and frozen EEG examples. Same-input speedups of 154–1730 times, batch processing and optional low-memory execution expand the practical scale of GSBS while preserving its scientific outputs.

A single boundary replaces one interval by two; a double boundary replaces it by three. HP-GSBS reuses all unaffected contributions. The unscored sentinel, first-maximum rule and nonfinite-score handling are explicitly tested against the reference implementation. Candidate proposals maximize the matching score; the subsequent single-versus-double decision uses t-distance. Refinement deletes and reinserts boundaries sequentially, retaining their insertion labels. In a double insertion, adjacent state-count slots can share a partition; the last accepted partition may contain Kmax + 1 states. The full arrays retain this indexing.

# S3 Execution interfaces and numerical scope 

The stable configuration combines FP64, Full-Q, streaming candidates and Prefix2D t-distance. CPU, PyTorch CUDA and Triton share this controller. An optional independent input Y supplies t-distance data while X continues to determine candidates and state patterns. Near-tied candidate scores are reevaluated with the original expression. Such guards preserve the measured decision paths, while practical tolerances remain distinct from an error bound over all floating-point inputs. Spatially constant rows and nonfinite inputs are rejected; the documented handling of ill-conditioned but otherwise valid matrices follows the reference pathway. Resource budgets limit candidate enumeration, original-expression reevaluation, workspace and tiled pair evaluation. Budget refusal does not change the candidate domain or scientific parameters. Reusable research workflow 

The executable scripts/research_workflow.py generates a small prepared input, fits it on CPU, retrieves boundaries and t-distance, saves and reloads a versioned result, and processes two recordings independently.
