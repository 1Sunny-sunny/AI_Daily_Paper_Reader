A B S T R A C T 

Spatial encoding lets a spiking neural network classify a value without a temporal integration window, by presenting it as one pattern of simultaneous spikes, but makes classification depend on the geometry of the binary code. In standard binary, adjacent values such as 127 and 128 differ in every bit, a “Hamming cliff” that forces supervised STDP networks with homeostasis into excessive scaling and false positives. We present a controlled characterisation of this dependence rather than an application benchmark: every experiment runs on SpiNNaker hardware, in a dual-rail network with a single output neuron, and presents every value of a synthetic integer range. Gray, Thermometer and Johnson encodings all remove the cliff, but only Thermometer and Johnson preserve global semantic distance, at a width that grows linearly with the range. We introduce a family of hybrid encodings, combining a coarse magnitude code with a Gray code for fine position, that contains all three as exact limiting cases of a single parameter; a sevenfold reduction in width costs one percent of the correlation between Hamming and semantic distance. The homeostatic factor sets a Hamming radius of tolerance that the network follows exactly in 93% of conditions, and elsewhere to within one bit, so the encoding alone determines what that tolerance means: a contiguous interval for Thermometer and Johnson, wrapping at the range ends for the cyclic codes, and scattered values for Binary and Gray. Measuring the limit on simultaneous input on SpiNNaker and SpiNNaker2, we show that on SpiNNaker it is a silent software default, and that the hybrids remain within it at 1024 values where their parent codes do not. Evaluation on a downstream task, such as network-traffic classification, is left to future work. 

## 1. Introduction 

Artificial Neural Networks (ANNs) owe much of their success to gradient-based training (Linnainmaa, 1976; Schmid-huber, 2015). In these second-generation networks (Maass, 1997), inputs are continuous values, so numerically adja-cent inputs map to adjacent activation levels and semantic proximity is preserved by construction; biologically, this corresponds to a rate code, in which firing frequency carries

By pre-processing input signals with Gray, Thermometer, Johnson and hybrid encodings before passing them to spiking neural networks run-ning on SpiNNaker hardware, Davies et al. address the semantic-spatial dis-parity that causes the “Hamming cliff” in standard binary representations. Continuous semantic patterns are presented as a set of simultaneous spikes at the input layer, preserving ultra-low latency processing. Training the network on multiple continuous values under each scheme, and measuring accuracy, required homeostatic scaling and false-positive rates, shows that removing the cliff is necessary but not sufficient: Gray encoding removes it yet retains little global distance structure, whereas Thermometer and Johnson preserve semantic distance at a code width that grows with the value range. The proposed hybrid encodings contain all three as limiting cases of a single parameter, recovering most of that structure at a fraction of the width. Third-generation Spiking Neural Networks (SNNs) (Maass, 1997) add time to the model, and a rate code then costs latency: to decode a value, the network must “wait and count” spikes over an integration window. It also costs energy. Event-driven neuromorphic hardware spends its energy per event rather than per clock cycle, routing every spike as a packet and processing it at each synapse it reaches (Furber et al., 2014; Davidson and Furber, 2021), so a code that spends many spikes on each value undermines both the low latency and the low power that such hardware promises (Davies et al., 2018). Spatial encoding avoids this bottleneck by representing a value as a pattern of simultaneous spikes (Davies et al., 2025). Because neuromorphic hardware delivers informa-tion through discrete, addressable synapses, the value is first converted to a binary code word, and each bit is signalled by the presence or absence of a spike from one source (Auge et al., 2021). The input activity per decision is then fixed by the code width, and the output is delayed only by the depth of the network (Göltz et al., 2021). The conversion to binary, however, introduces a structural vulnerability, the “Hamming cliff” (Caruana and Schaffer, 1988): numerically adjacent values can have very different code words. The 8-bit range is used for most of our experiments, as the widest at which every encoding compared here fits within the default input limit of first-generation SpiNNaker (Section 3.4). In earlier work (Davies et al., 2025), we showed that an SNN trained with supervised STDP classifies a single spatial pattern accurately, but that its performance degrades when it is trained on several. Large Hamming distances between the trained patterns create “don’t care” synapses, which receive conflicting evidence from different patterns and so contribute nothing to the output; the network must then rely on stronger homeostatic scaling, which sharply increases false positives. Standard binary encoding therefore prevents the network from recognising contiguous ranges of values. This matters wherever the inputs are continuous or ordinal. In network-traffic classification, for instance, packet sizes, flow durations and inter-arrival times carry meaning in their proximity: two flows of similar duration are similar events, and an encoding that maps them to distant spatial patterns discards that information before the network sees it. Other features are cyclic: time of day is the clearest case, where 23:59 and 00:00 are adjacent, and such features need an encoding whose topology reflects that. This paper examines spatial encodings that restructure the signal before it reaches the network, while keeping one spike per bit. The established alternatives are not equivalent: Gray encoding removes the cliff but preserves little global distance structure, whereas Thermometer and Johnson en-codings preserve it at the cost of a code width that grows linearly with the value range. We introduce a family of hybrid encodings, which combine a coarse magnitude code with a Gray code for fine position; the family contains all three as limiting cases of a single parameter and trades code width against preservation of semantic distance at a favourable rate. On hardware, the homeostatic factor sets a radius of tolerance in code space around each trained code word, so the encoding alone decides which values the net-work treats as similar. The same analysis explains the degra-dation observed in our earlier work (Davies et al., 2025): the summed weights of trained code words cancel wherever they disagree, and the homeostatic gain that compensates is what admits the false positives. Because a spatial code delivers all its bits at once, its width is also bounded by the number of simultaneous input events a neuron can receive: about 255 under the default configuration of first-generation SpiNNaker, and 512 on SpiNNaker2 (Mayr et al., 2019; Gonzalez et al., 2024). The hybrid construction reduces code width by an order of magnitude. To our knowledge, this is the first systematic characterisation of how the choice of spatial code governs the homeostatic scaling, and hence the tolerance and false-positive behaviour, of supervised STDP learning on neuromorphic hardware. The main contributions of this work are: • an account of how the geometry of a spatial code sets the homeostatic tolerance of a supervised STDP network (Sections 4.3.1 and 4.4); • a hybrid coarse–fine encoding family with Ther-mometer, Johnson and Gray as limiting cases (Sec-tion 3.5); • evidence that removing the Hamming cliff is neces-sary but not sufficient for semantic clustering (Sec-tions 4.1 and 4.3); • a characterisation of the per-neuron input limits on SpiNNaker and SpiNNaker2 (Section 3.4); • an exhaustive hardware evaluation of eight encodings, with code and data released (Sections 4.2–4.5). The scope of this work is deliberately narrow: we char-acterise the encodings rather than evaluate them on a task. Every experiment presents every value in the range to the trained network, so the relations reported are exact over the whole input space and a relation such as the tolerance law of Section 4.4 can be checked condition by condition. A natural dataset allows neither: its values are unevenly distributed and its features correlated, so the effect of code geometry on learning would be confounded with the data. The network (a dual-rail input layer feeding a single output neuron), the learning rule and the measurement protocol are held constant, so the encoding is the only variable, and the comparison throughout is against standard binary encoding, the representation used in our prior work. How the ranking carries over to a downstream task, where feature distributions are uneven and the encodings interact with later processing, is the subject of separate work. 

## 2. Theoretical Background 

2.1. Spatial Encoding and the Hamming Vulnerability 

In spatial encoding, all bits of a code word are presented to the network in the same timestep, so the network has no access to the value itself, only to which of its input synapses are active. Its response to two values therefore depends on how many bits their code words share, that is, on the Hamming distance between them. In the supervised STDP network of Davies et al. (2025), a larger Hamming distance between trained code words required a larger homeostatic scaling factor for all of them to be recognised, and the larger factor admitted more false positives. The following subsections formalise this dependence and the properties of the encodings that determine it.

2.3. Encoding Topologies 

To address the Hamming cliff, we consider alternative mapping techniques that constrain the relationship between semantic and spatial distance: • Gray Encoding: A reflected binary code where adja-cent integers are represented by codewords that differ by only a single bit, ensuring minimal spatial tran-sitions between semantically adjacent states (Gray, 1953). • Thermometer Encoding: Maps a magnitude by pro-gressively filling a bit-field, creating a unary represen-tation: the value is given by the number of bits set, not by which particular bits are set (Buckman et al., 2018). Representing 𝑁 values therefore requires 𝑁 − 1 bits, and successive values differ in a single bit. • Johnson (Twisted Ring) Encoding: A cyclic code in which bits are set one at a time from one end of the field and then cleared again from that same end, so that 

𝑊 bits generate 2𝑊 distinct states before returning to the start (Mano and Ciletti, 2012). Successive values differ in a single bit, and because the sequence closes on itself the first and last values are adjacent. These codes are long established in digital logic. The criterion that bit-flip distance should track semantic distance is also established in the weightless neural network liter-ature, where binary encodings for WiSARD are evaluated on exactly this basis (Kappaun et al., 2016), and unary thermometer codes are the standard solution (Bacellar et al., 2022). Codes that combine a coarse unary field with a fine binary one are likewise familiar from segmented data converters. What has not been examined is their use as spatial codes for spiking neural networks, where each bit is a discrete synapse, all bits are presented simultaneously, and homeostatic scaling determines which code words the network accepts. 2.4. Topological Analysis 

The structural utility of these schemes is best understood through their distinct topological properties, as defined in digital logic theory (Mano and Ciletti, 2012). Thermometer encoding enforces linear boundary conditions on the se-mantic space, wherein the minimum and maximum values are maintained at maximal Hamming distance. Conversely, Johnson encoding imposes a periodic topology; by forming a ‘twisted ring’, the encoding identifies the semantic extremes 

0 and 𝑁 −1 as adjacent, regardless of the code width 𝑊 . This cyclic property makes Johnson encoding a natural candidate for quantities with circular continuity, such as orientation, phase or time of day, whereas Thermometer encoding suits bounded magnitudes. These schemes must, however, be distinguished by which 

property they preserve. All three guarantee local smooth-ness: values adjacent under the metric each is designed for differ in a single bit, eliminating the cliff of Section 2.2. Only Thermometer and Johnson additionally preserve global 

structure, each exactly under its own metric: 𝐻 (𝑐 𝑖 , 𝑐 𝑗 ) =

𝑑 lin (𝑖, 𝑗 ) for Thermometer and 𝐻 (𝑐 𝑖 , 𝑐 𝑗 ) = 𝑑 cyc (𝑖, 𝑗 ) for Johnson. Gray encoding offers no such guarantee. Its re-flected construction places every value 𝑖 a single bit from 

2𝑊 −1− 𝑖 , however far apart the two are, so that the extremes 

0 and 2𝑊 − 1 differ in one bit; Hamming distance therefore carries little information about semantic separation beyond immediate neighbours. Removing the Hamming cliff is therefore necessary but not sufficient for the clustering behaviour sought here, and Section 4.1 quantifies the gap between the two properties. These three codes are not, however, exclusive alternatives: the reflected construction of Section 3.5 interpolates be-tween them and contains all three as limiting cases. 

2.5. Relation to Other Low-Latency Representations 

Spatial binary codes are one of several ways to give a spiking network a fast decision about a scalar (Auge et al., 2021). They are distinguished from the others by three properties: when the decision becomes available, how many input events it costs, and how the distance between code words relates to semantic separation (Table 1). Latency coding, or time to first spike, represents a value by when a single spike occurs (Mostafa, 2017; Göltz et al., 2021). It is frugal in events, one per input neuron, and preserves proximity naturally, since close values fire at close times; but the decision cannot be taken until the latest spike that could carry information has had time to arrive, so its latency is bounded by the encoding window rather than by the depth of the network. Rank-order coding (Thorpe and Gautrais, 1998) reads information from the order in which a population fires. It is equally frugal, but it encodes the relative ordering of several inputs rather than the magnitude of one, and it too must wait for that order to be established. Both trade time for events. Spatial codes make the opposite trade: every bit is delivered in the same timestep, so the decision follows within a fixed number of timesteps of the input, and the cost is paid in width instead. Population coding with Gaussian receptive fields (Bohte et al., 2002) preserves semantic proximity through over-lapping graded fields, and is usually read out in time, the strength of each field becoming the latency of its spike. Binarised and presented spatially, it becomes a window of 𝑘 

active neurons that moves with the value, and its Hamming distance at semantic separation 𝑑 is 2 min( 𝑑, 𝑘 ): proximity is preserved within the width of a field and lost beyond it, every pair of values further apart than 𝑘 being equidistant. One-hot, or place, coding is the limiting case 𝑘 = 1, in which every pair of distinct values lies at distance 2 and code distance carries no information about separation at all. A place-coded population is nevertheless the natural input layer from which a spatial code can be computed on-chip, and in a single-rail arrangement it costs only one event per value; the dual-rail wiring used here, in which every bit must be presented, removes that advantage. The spatial codes studied in this paper differ from all of these in that distance in code space, rather than in time, carries semantic separation, and they differ from one another in how much of it survives. Thermometer and Johnson preserve it exactly and globally, where a population window preserves it only within its own width, and the hybrid con-struction introduced here preserves it globally at a fraction of the width. It is this global structure, rather than local smoothness alone, that homeostatic tolerance turns into a semantic interval. 

## 3. Methods 

3.1. Network Architecture 

The network follows the supervised STDP arrangement of Davies et al. (2025). A code word is presented as a dual-rail spatial pattern: for each bit, one neuron fires if the bit is 1 and a second fires if it is 0, so exactly one of the two rails is active per bit and the whole code word is presented within a single simulation timestep. All neurons are leaky integrate-and-fire units with delta synapses, which deliver their current within one timestep, with the parameters listed in Table 2.

Each of the eight encodings has its own dual-rail pair and its own output neuron, and all eight are trained in a single simulation; the pattern generator, save neuron and teacher neuron are shared between them. 

3.1.3. Deviations from the previous work 

Two parameters differ from Davies et al. (2025), both required by the wider code words used here. First, the output neuron’s firing threshold is scaled with the code width. A width-𝑊 code delivers up to 𝑊 potentiated synapses’ worth of current in a single timestep, which for wide codes exceeds the default threshold and causes the output neuron to fire without the teacher, corrupting the learned pattern; the threshold is therefore set to twice the accumulated drive, subject to a floor at the default value. Second, the STDP weight ceiling 𝑤 𝑚𝑎𝑥 is reduced from 

20 to 2. The simulator holds synaptic weights in a fixed-point accumulator whose scaling is fixed at run time by the largest total current that could arrive at a neuron, namely 𝑤 𝑚𝑎𝑥 

times the fan-in (van Albada et al., 2018); a larger product consumes more integer bits and leaves fewer fractional ones, coarsening the resolution. At the widest code considered the fan-in reaches 510 , two rails of 255 bits, and at the default ceiling the resulting step size is comparable to the learned weight of ≈ 0.37 itself, which therefore cannot be represented. Lowering the ceiling restores the fractional precision, and the learned weight is then recorded as 0.375 .Neither affects what is learned: homeostasis rescales the weights afterwards, and Davies et al. (2025) note that the STDP parameter values are of little consequence for exactly this reason. A corollary is that the absolute homeostatic factors of encodings with different widths are not directly comparable, since their thresholds differ; comparisons in Section 4 are therefore made within an encoding, or after normalisation. 

3.2. Application of the Encoding 

The encoding is applied as a pre-processing step rather than computed by the network. For a given value, the code word determines the connectivity: the generator neuron that fires at the “1” times (Section 3.1) connects to every bit of the code word equal to one, and the neuron that fires at the “0” times to every bit equal to zero. The network is therefore constructed anew for each value presented, and no population computes the mapping from value to code word. This matches the framing of the work as a pre-processing of the input signal, and it also removes the source-side spike load: each generator neuron emits one packet per presentation time, which the router fans out, rather than one packet per bit. The same mapping could be computed on-chip, by a place-coded input population with one neuron per value projecting to the bits of its own code word through fixed connectivity. Such a network would present identical activity to the encoding populations, so the results reported here do not depend on which of the two arrangements is used.

3.4. Input Capacity and Spatial Code Width 

Because all bits of a spatial code word are presented simultaneously and each bit fires on exactly one rail, a code of width 𝑊 delivers 𝑊 spike packets to its output neuron within a single timestep. Any limit on the number of packets a neuron can receive at once is therefore a limit on code width. We measured this limit on both platforms. 

3.4.1. SpiNNaker 

sPyNNaker places incoming packets in a circular buffer on each core, allocated with 256 slots by default, of which one is always kept empty, so that at most 255 packets can be held; packets that arrive when the buffer is full are discarded without error. Training an output neuron on code words of increas-ing width under the default configuration, the number of synapses potentiated tracked the width exactly up to 255 

and then stopped, at 255 or occasionally 256 when a packet was consumed during the burst, for widths of 300 , 480 and 

992 . Raising the buffer to 1024 slots removed the limit: every synapse was potentiated at every width tested. The bound is therefore a default of the software rather than a property of the hardware. It is, however, silent: the network learns a truncated pattern while reporting no fault, and the downstream metrics remain plausible. To see whether the limit is a fixed capacity, the mea-surement was repeated under the default buffer with static synapses, as used in the testing network, counting the inputs delivered from the deflection of a non-leaking membrane. Here the limit is neither fixed at 255 nor abrupt: every input arrived up to 385 , and beyond that about two in five additional inputs still did. Spreading the same inputs across two and four source populations raised the point at which loss began to 426 and 435 . Both observations indicate a buffer that drains while it fills: spreading the inputs spreads   

> Davies, S. et al.: Preprint submitted to Elsevier Page 7 of 25 Beyond the Hamming Cliff: Compact Spatial Encodings Preserving Semantic Distance in Spiking Neural Networks

their arrival in time, and static synapses are cheap enough to process that the buffer empties appreciably during a burst. Plastic synapses cost more per spike, so during training it barely drains and its depth alone sets the limit. The limit was the same at every synaptic weight tested, so it is a count of events rather than of current. 

3.4.2. SpiNNaker2 

The same deflection measurement on SpiNNaker2 shows a different kind of limit. Every input event reaches the neuron up to 512 simultaneous inputs, and delivery stops abruptly there: 513 inputs produce the deflection of exactly 512 . The limit is the same at every synaptic weight tested and does not change when the inputs are split across several source populations, so it is a count of input events per neuron rather than a bound on current or on the traffic from a single source. The measurements were made with the default configura-tion of py-spinnaker2; whether the limit can be configured, and whether it bounds events per timestep or connections per neuron, was not established. For spatial codes the two coincide, since every bit of a code word is delivered in the same timestep. 

3.4.3. Consequences for the encodings 

Since a code of width 𝑊 delivers 𝑊 input events, each limit bounds the range of values an encoding can represent. Under SpiNNaker’s default buffer of 255 packets, Ther-mometer, which needs 𝑁 − 1 bits, is limited to 256 values, and Johnson, which needs 𝑁 ∕2 , to 510 ; under SpiNNaker2’s limit of 512 input events per neuron the corresponding figures are 513 and 1024 . Binary and Gray need ⌈log 2 𝑁 ⌉

bits and are unconstrained in practice, and the hybrids lie between the two. Neither limit is fixed: SpiNNaker’s buffer can be en-larged, and SpiNNaker2’s limit appears to be a property of its current software. What is fixed is the cost: a spatial code requires one packet, one buffer entry and one synaptic event per bit for every decision, so enlarging the buffer accommodates a wide code but does not make it cheaper. The experiments here use the default configuration, under which 𝑁 = 256 is the widest range at which every encoding fits. 3.5.7. Width and input activity 

Because every bit costs one spike packet per classifica-tion, width is the number of input events per decision. On event-driven hardware the dynamic energy of a computation grows with the number of events it involves (Furber, 2012; Davidson and Furber, 2021), so width bounds the input contribution to that energy; energy itself was not measured here. Width is also the number of buffer entries each decision occupies on the receiving core (Section 3.4).

4.2.1. A systematic effect of bit count 

Under Binary, the required scaling factor varies slightly between second values at equal Hamming distance, and the variation is not noise. It depends on the number of 1-bits in the second code word and not on their position. At 𝐻 = 1 

the second value differs from the anchor 240 10 = 11110000 2

in a single bit. The four values that do so by setting one of its zero bits, 241 , 242 , 244 and 248 , each have five set bits, and all require exactly 2.96051 , although the flipped bit occupies a different position in each. The remaining one-bit neighbour, 224 , clears a set bit instead and so has three, and it requires 2.95312 (the search records the factor to five decimals; the tables report it rounded up to two). At 𝐻 = 4 

the factor rises monotonically with bit count, from 5.13955 

for 0 (no set bits) through 5.18480 for 238 (six) to 5.19773 

for 255 (eight). Within any Hamming-distance group the spread is at most 1.1% .This follows from the dual-rail training protocol. Bits equal to 1 and bits equal to 0 are presented at different times relative to the teacher spike (Section 3.1), so their synapses are potentiated at different points on the STDP curve and need not acquire identical weights. A code word with more set bits therefore draws proportionally more of its drive from one rail and requires marginally more gain to reach threshold. The effect is an order of magnitude smaller than the differences between encodings reported here and does not affect any comparison, but it accounts for the residual variation within a Hamming-distance group, and it reappears in Section 4.4 where the tolerance threshold falls exactly on a boundary between Hamming distances.

## 5. Discussion 

The results support four main conclusions about spatial representation in the SNN architecture studied here. First, homeostatic scaling acts in code space rather than semantic space. For a single trained pattern, increasing the gain enlarges the set of code words whose Hamming dis-tance from the target remains within the firing threshold. Equation (13) predicts this Hamming radius from code width and gain alone, and the hardware measurements reproduce the predicted accepted set exactly in 238 of 256 conditions; of the remaining 18 , sixteen admit one further Hamming shell where the predicted radius falls just short of an integer and the resolution of the homeostatic search tips it over, and two fall exactly on a shell boundary, where the small asym-metry between rail weights determines which code words fire. What this tolerance means semantically is therefore decided entirely by how the encoding embeds the underlying variable. Second, local continuity and global distance preserva-tion are distinct properties. Gray encoding guarantees a one-bit transition between adjacent values and so removes the Hamming cliff, but its global Hamming distance is only weakly related to semantic separation: 𝜌 𝑠 = 0 .374 , barely above Binary’s 0.323 . Thermometer and Johnson encode lin-ear and circular distance exactly, and the hybrids retain most of this structure at much smaller widths. This explains why Gray performs well when the trained values form a compact cluster, yet needs progressively more homeostatic margin as the trained set grows, reaching 1.61 times the coherent value, whereas Thermometer, Johnson and the hybrids stay within 

21% .Third, the interaction between several learned patterns can be predicted from their code geometry. In the bipolar representation of Eq. (12), agreement between two code words reinforces the accumulated synaptic drive and dis-agreement cancels it, so the additional homeostatic factor required by a trained set follows from its pairwise Hamming distances, with a maximum discrepancy of 0.03 from the measured values (Section 4.3.1). The same mechanism ex-plains the large gain that Binary encoding requires, and why its acceptances follow the bits that values share rather than their proximity: scattered across the range at 256 values, and at 1024 values the aligned block of values sharing the three highest bits of the trained values. Fourth, semantic structure has a hardware cost. A spatial code of width 𝑊 delivers 𝑊 input events to the receiving neuron for every decision, and the number of simultaneous   

> Davies, S. et al.: Preprint submitted to Elsevier Page 17 of 25 Beyond the Hamming Cliff: Compact Spatial Encodings Preserving Semantic Distance in Spiking Neural Networks

input events a neuron can accept bounds the usable width: about 255 under the default configuration of first-generation SpiNNaker, where wider codes are silently truncated, and 

512 on SpiNNaker2 (Section 3.4). Thermometer and John-son offer exact distance preservation at an event count that grows linearly with the number of represented values, while the block size of the hybrids controls how much global structure and neighbourhood contiguity is kept for a given width. The choice is therefore not simply between “accurate” and “compact” codes, but between combinations of semantic topology, tolerance resolution and per-decision event load. In practice, this suggests a simple rule: choose a cyclic or linear code to match the topology of the variable; use Thermometer or Johnson when the range fits within the input limit; and otherwise use the smallest block size whose width, from Eq. (10), fits within it, since smaller blocks keep neighbourhoods more contiguous. 

5.1. Limitations 

The evaluation uses synthetic values over a single range at a time, one network architecture, and first-generation SpiNNaker for every result except the input-capacity mea-surements. The experiments ran slower than real time, so the processing cost of wide codes, which would bound the rate of decisions at real time, was not measured. On SpiNNaker2 we established the limit of 512 input events per neuron but not its origin: whether it can be configured, and whether it limits events per timestep or connections per neuron, remain open. The results are also drawn from a single output neuron; the tolerance law is derived per neuron and should extend to a layer of independently trained neurons, but this is not demonstrated here. The weight vectors for multiple trained values are ob-tained by training each value separately and summing, not by presenting the values sequentially or interleaved to a single plastic network. This is a deliberate idealisation: it makes the learned vector an exact linear function of the trained set, which is what allows the coherence ratios of Section 4.3 to be predicted from pairwise Hamming distances alone (Section 4.3.1). Sequential STDP would not be linear in the same way. The nearest-pair rule pairs each presentation only with its nearest post-synaptic spike, so the update a value induces depends on what has already been learned, and the weight ceiling of 2 would clip bits on which several trained values agree: at a learned weight of about 0.375 per value, synapses shared by six or more values would saturate, and the coherent scaling of 𝑓 (1)∕ 𝑛 would cease to hold. Whether on-chip sequential learning converges to the summed vector for small trained sets, and how it departs from it for large ones, remains to be tested. No downstream dataset or multi-feature classification problem is evaluated, and the introduction explains why: the exhaustive protocol that makes the relations above exact is not available on a natural dataset. The consequence is that nothing here shows how the encodings behave when several features are presented together. One difficulty is already visible from the tolerance law: if features are concatenated into one code word, the Hamming distance is the sum of the per-feature distances and the tolerance radius applies to that sum, so a large deviation in one feature can be offset by exact agreement in the others. A multi-feature classifier built on these encodings would need either per-feature detectors with their own radii or a weighting across features, and the choice between them is an open design question. The hybrids do not fully reproduce their parents’ be-haviour. Their accepted sets are fragmented into up to 𝐵 

runs by the Gray fine field, and their false positives, though confined near the trained cluster, are less tightly concentrated than Thermometer’s. The block size therefore trades not only correlation but neighbourhood contiguity, and smaller blocks should be preferred where contiguity matters. The tolerance law is exact only to the resolution of the homeostatic search: rounding the factor upwards can admit one further Hamming shell wherever the predicted radius falls just short of an integer, which occurred mostly in the widest code, and a finer search would be needed to exploit Thermometer’s full precision. Finally, the hybrid construc-tion resembles the segmented thermometer-plus-binary ar-chitectures of data-converter design, and the contribution here is the Gray fine field with reflected block ordering and its characterisation in a neuromorphic setting, rather than the two-level idea itself. 

## 6. Conclusions 

Spatial encoding removes the latency of rate coding but makes classification depend on the geometry of the code. For a dual-rail network with a single output neuron on first-generation SpiNNaker, homeostatic scaling sets a Hamming radius around each trained code word, and the encoding alone decides what that radius means: a contiguous interval of values for Thermometer and Johnson, wrapping at the ends of the range for the cyclic codes, and a scattered set of values for Binary and Gray. The encodings commonly proposed against the Ham-ming cliff are therefore not equivalent. Gray removes the cliff but discards global distance structure, and pays for it in homeostatic margin as trained sets grow; Thermometer and Johnson preserve that structure at a width that grows with the value range. The hybrid construction introduced here contains all three as limiting cases of a single block-size parameter and trades width against preservation of semantic distance at a favourable rate: the cyclic hybrid at 𝐵 = 8 

accepts no untrained value as the trained cluster grows, in 

19 bits where Johnson needs 128 .Width matters because it is the number of input events paid on every decision, and both platforms bound it: on SpiNNaker by a configurable buffer of the simulation soft-ware, which by default silently truncates codes wider than 

255 bits during training, and on SpiNNaker2 by a limit of 

512 input events per neuron. The hybrid construction re-duces width by roughly an order of magnitude while leaving the radius of the detected neighbourhood unchanged. Future work will apply these encodings to network-traffic classification, where continuous, ordinal and cyclic
